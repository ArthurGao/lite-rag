# S25 Lineage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generic provenance ledger (`lite_rag.lineage`) recorded by lite-rag's write paths in the same transaction, plus opt-in query traces that say which chunk versions a search / answer used and whether they have since gone stale.

**Architecture:** `lite_rag.lineage` knows only artifacts, versions and edges; it works inside the caller's connection and transaction (`PgLedger` / `SqliteLedger`). lite-rag's stores call a thin RAG-side module (`lite_rag/provenance.py`) inside their existing upsert / delete transactions. Traces live in lite-rag tables and key each source by the chunk's `lineage_key`, stored on the chunk row and read at retrieval time.

**Tech Stack:** Python 3.12, uv, psycopg 3, sqlite3, pydantic-settings, Typer, pytest, ruff, mypy.

**Spec:** `docs/superpowers/specs/2026-11-24-lineage-design.md` (read it first; this plan names files, signatures and tests, the spec gives the why).

## Global Constraints

- `lite_rag/lineage/` imports only the standard library, `psycopg` and itself — never another `lite_rag.*` module (spec §5.4).
- Ledger tables are prefixed `lineage_`; ledger migrations record into `lineage_schema_migrations`.
- Chunk ledger key: `f"{doc_id}/{text_hash[:16]}/{k}"`, `text_hash = sha256(Chunk.text)` hex, `k` = 0-based occurrence of the same text within the document (spec §6.1).
- Position and context live on the edge (`chunk_id`, `n`, `start`, `end`, `page`, `parent_n`, `context`), never in the chunk artifact.
- Times are written from a Python clock (`datetime.now(UTC)`, injectable), never DB `now()` / `CURRENT_TIMESTAMP` (SQLite has second resolution; `as_of` needs order).
- Config defaults: `lineage.enabled: true`, `lineage.keep_text_days: 90`, `trace.enabled: false`, `trace.query: text` (`text|hash|none`), `trace.retention_days: 90`.
- Existing `search` / `search_kbs` signatures and return values unchanged; new `search_traced` / `search_kbs_traced` return `Traced(hits, trace_id)`; `record_cited(trace_id, chunk_ids)`.
- Trace write failures raise (rule 5); a source missing from the ledger is shown as "未记录"/`unrecorded`, never an error.
- Tests: fakes only; PG tests via `uv run --env-file .env pytest` in schema `lite_rag_test`; every new test seen red once.
- Never commit without the owner's go-ahead for that commit; `git add <paths>` only. Work on a branch per stage (`feat/s25a-lineage-ledger`, …), as earlier stages did.
- Each stage ends with the close-out in `CLAUDE.md` (simplify → Codex `exec -s read-only … < /dev/null` → fix → re-run every check) before the next stage.
- Full check: `uv run ruff check && uv run ruff format --check && uv run mypy && uv run --env-file .env pytest`.

## Review Focus

- A re-upsert that changes only the title or metadata: new document version, every chunk artifact reused, none superseded (Task 5).
- A document whose new version has zero chunks (empty text): new document version recorded, every old chunk superseded (Task 5).
- The same `doc_id` in two kbs (and `reindex` into a new kb): separate namespaces; deleting in one leaves the other active (Task 5).
- `delete` of a document that does not exist: returns False, ledger unchanged, no error (Task 5).
- `search_kbs_traced` over two kbs: each source's `artifact_ns` is its own kb's physical key (Task 8).

### Task 2: Recording and retiring

**Files:**
- Create: `src/lite_rag/lineage/ledger.py`

**Interfaces:**
- Consumes: Task 1 types and `ledger_conn`.
- Produces: `class Ledger(Protocol)` and `PgLedger(conn, clock=utcnow)`, `SqliteLedger(conn, clock=utcnow)` with
  - `record(namespace: str, kind: str, key: str, content_hash: str, *, parents: Sequence[str] = (), producer: str | None = None, payload: str | None = None, metadata: dict[str, Any] | None = None, edge_metadata: dict[str, Any] | None = None) -> Recorded`
  - `retire(artifact_id: str, *, status: Literal["superseded", "deleted"] = "superseded") -> list[Artifact]`
  - `retire_namespace(namespace: str, *, status: Literal["superseded", "deleted"] = "deleted") -> int`
  - `utcnow() -> datetime` (module-level, `datetime.now(UTC)`).
- Semantics (spec §5.3):
  - `record`: an active artifact with the same `(namespace, kind, key)` and `content_hash` → `reused=True`, edges from `parents` added (existing edge: its metadata replaced). Otherwise a new artifact `version = max+1` (1 if none); a previous active one is marked `superseded` with `ended_at=clock()` **without cascading** and returned as `replaced`.
  - `retire`: ends the artifact if still active (status + `ended_at`), then — also when it was already ended — ends each active child that has no active parent left, recursively. Returns what it ended now, itself first if it was active.
  - A missing `parents` id raises `ValueError`. Nothing commits.
